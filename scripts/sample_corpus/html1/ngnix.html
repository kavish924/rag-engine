Nginx Guide

Nginx is a high-performance web server, reverse proxy, load balancer, and HTTP cache. It is widely used for serving static content, routing application traffic, SSL termination, and improving application scalability.

Key Features

  • High Performance
  • Reverse Proxy
  • Load Balancing
  • SSL Termination
  • Static File Serving
  • HTTP Caching

Architecture

Nginx follows an event-driven asynchronous architecture. Unlike traditional web servers that create one thread per connection, Nginx efficiently handles thousands of concurrent connections using a small number of worker processes.

Master Process

The master process reads configuration files, starts worker processes, and manages reloads.

Worker Processes

Worker processes handle incoming HTTP requests. Each worker can process thousands of simultaneous connections efficiently.

Installation

Ubuntu

sudo apt update

sudo apt install nginx

CentOS

sudo yum install nginx

Start Service

sudo systemctl start nginx

sudo systemctl enable nginx

Configuration File

The main configuration file is usually located at: 

/etc/nginx/nginx.conf

Additional site configurations are commonly stored in: 

/etc/nginx/sites-available/

/etc/nginx/sites-enabled/

Basic Server Block

server {

    listen 80;

    server_name example.com;

    root /var/www/html;

    index index.html;

}

Reverse Proxy

A reverse proxy forwards client requests to backend application servers while hiding their internal implementation. 

server {

    listen 80;

    location / {

        proxy_pass http://localhost:8000;

    }

}

This configuration is commonly used for FastAPI, Django, Flask, and Node.js applications.

Load Balancing

Nginx can distribute incoming requests across multiple backend servers. 

upstream backend {

    server 10.0.0.1;

    server 10.0.0.2;

    server 10.0.0.3;

}

server {

    location / {

        proxy_pass http://backend;

    }

}

Load Balancing Algorithms

  • Round Robin
  • Least Connections
  • IP Hash
  • Weighted Round Robin

Serving Static Files

Nginx is optimized for serving HTML, CSS, JavaScript, and image files. 

location /static/ {

    root /var/www/project;

}

HTTPS Configuration

SSL certificates enable encrypted communication between clients and servers. 

server {

    listen 443 ssl;

    ssl_certificate certificate.crt;

    ssl_certificate_key private.key;

}

HTTP to HTTPS Redirect

server {

    listen 80;

    return 301 https://$host$request_uri;

}

Compression

Gzip compression reduces response size and improves page load performance. 

gzip on;

gzip_types text/plain text/css application/json;

Caching

Nginx can cache responses to reduce backend load and improve response time. 

proxy_cache_path /tmp/cache levels=1:2
keys_zone=my_cache:10m;

Security Best Practices

  • Disable server version exposure.
  • Use HTTPS.
  • Enable security headers.
  • Limit request size.
  • Restrict directory listing.
  • Use firewall rules.
  • Keep Nginx updated.

Monitoring

Monitor CPU usage, memory consumption, active connections, request rate, and response time.

Troubleshooting

502 Bad Gateway

  • Backend application is down.
  • Incorrect proxy_pass address.
  • Firewall blocking backend.

404 Not Found

  • Incorrect root directory.
  • Missing index file.
  • Wrong location block.

Permission Denied

  • Incorrect file ownership.
  • SELinux restrictions.
  • Directory permissions.

Useful Commands

sudo nginx -t

sudo systemctl restart nginx

sudo systemctl reload nginx

sudo systemctl status nginx

Best Practices

  • Separate configuration into multiple files.
  • Always validate configuration before reload.
  • Use HTTPS in production.
  • Enable gzip compression.
  • Configure caching for static assets.
  • Monitor logs regularly.
  • Limit request rates to prevent abuse.

Summary

Nginx is one of the most widely used web servers and reverse proxies in cloud-native applications. It efficiently serves static content, balances traffic across backend services, provides SSL termination, and integrates seamlessly with FastAPI, Docker, Kubernetes, and cloud infrastructure.
